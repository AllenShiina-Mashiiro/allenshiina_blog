
# 通用next.js项目开发思路

1.项目架构以：
React，Next.js，TypeScript，
PostgreSQL 18，Prisma，Linux ，Nginx
【补充】Redis（用于缓存与WebSocket Pub/Sub），对象存储（如阿里云OSS/腾讯云COS，强烈建议用于图片存储）
【补充安全警告】所有敏感配置（数据库密码、OAuth Secret、SMTP授权码）必须放入 `.env` 文件中，并加入 `.gitignore`，严禁上传至GitHub！文档中出现的邮箱授权码请立即作废重设！

登陆注册系统：
1.支持Gmail,QQ,网易,github登陆
2.注册账号逻辑：先填写自己的邮箱，获取到邮箱验证码，完成验证后注册成功，需要填写昵称（支持中英文，符号数字），密码，用户id
3.用户id逻辑：服务个人主页，实例：用户点击评论区的头像或者id自动跳转到对应的个人主页，且浏览器的路由显示的不是uuid，
而是以@example_username形式出现，比如以管理员为例：@allenshiina_admin(仅支持小写数字下划线)
包括用户查看自己的个人主页也能展现效果
【补充】用户ID路由需在后端做“保留字”拦截，禁止注册如 `@admin`、`@login`、`@settings`、`@api` 等系统路由冲突词。
【补充】需增加“忘记密码”/“重置密码”功能，通过SMTP发送重置链接。支持在账号管理中绑定/解绑第三方账号（如邮箱注册后绑定GitHub，需处理合并逻辑）。
4.SMTP六位邮箱验证码、Google OAuth、GitHub OAuth
5.访问主页和网站其他内容是不用强制登陆的，但是需要发表评论，点赞是需要注册登陆账号的
6.支持跳转快捷登陆，灵感参考x点击Google登陆的效果，若使用Google/QQ/github快捷登陆，则无需验证码

主页设计：
1.布局：以上传的图片展示效果为例
【补充】移动端适配：液态玻璃效果在移动端可能性能开销大，需在移动端通过CSS媒体查询降级或关闭复杂毛玻璃（backdrop-filter）效果，且侧边栏需折叠或移到底部。
2.主页的正上方的导航栏圆角美化，液态玻璃
3.主页导航栏里分别为logo图标，学习笔记、资源导航、时刻、动漫、聊天室、关于、搜索框、通知、翻译按钮（支持切换中英文网站）、浅色/深色切换按钮、个人中心按钮
4.logo图标：点击能返回到主页
5.学习笔记：点击后跳转到‘学习笔记’页面，支持创建新笔记，支持修改/删除笔记，发布笔记显示用户名，头像，时间（包括修改时间），笔记内容大体以markdown格式，
支持大中小标题，支持代码笔记高亮，支持代码复制按钮，支持插入图片，以便教学，支持标签，支持评论区，支持搜索笔记，支持‘图钉’（后文会具体描述功能）
6.资源导航：点击后跳转到‘资源导航’页面，示例：一个圆角美化的液态玻璃的ui，里面支持正方形的小封面图，在封面图右侧是标题，其下方是跳转按钮，支持点击跳转到对应链接
存在多个资源导航时，要自动排列布局，小卡片井然有序
7.时刻：点击后跳转到‘时刻’页面，灵感可以参考类似推特的广场的帖子，支持转发，点赞，回复，支持上传最多15张图片，若单张图片超过30MB，将其压缩到小于30MB.支持点击查看缩放图片，
支持原图下载；支持评论区
【补充】压缩建议在前端（浏览器端）使用Canvas API完成，减轻服务器压力；图片上传建议使用对象存储直传（后端签发临时Token），避免挤占Nginx带宽。
8.动漫：一个记录动漫的档案，目前只有管理员支持创建档案，支持上传封面，多图、标题，简介，作品的发布时间，来源，支持修改/删除
9.聊天室：点击后跳转到‘聊天室’页面分为官网组聊天室，和加入/创建聊天室，创建需要填写分类和名称，设置加入方式为：直接加入和邀请码加入，还有聊天室的频道的头像
灵感来源steam的聊天室，任何人都可以创建对应的聊天室，加入并聊天，目前暂时只支持文字和emoji的发送
发送显示昵称和头像还有时间，支持引用回复，参考telegram那种。
【补充】技术实现建议：Next.js 原生不支持长连接，实时聊天建议引入 Socket.io + Redis Pub/Sub，或者使用 SSE (Server-Sent Events)。
10.关于：点击跳转到‘关于页面’，关于页面里，类似贡献墙的设计，可以参考一下旧项目sakura-game-archive
且显示关于目前的网站的项目来源，版本号，提供开发者的贡献，以及其他的贡献者的贡献，支持跳转到开发者的github和主页；网站声明
11.暂不支持私信的功能，网站的回复消息的方式类似bbs只能在‘时刻’里的帖子评论区或者学习笔记的评论区发表且回复，发表评论支持修改和删除，支持显示发送/修改时间
且若删除评论，不展示，刷新页面会正常消失，避免存在展示已经删除的提示，但遗留无效评论
12.搜索框：支持搜索全站的内容，支持分类，标签，时间排序；搜索到的结果排列出列
【补充】建议使用 PostgreSQL 的全文检索（如 `tsvector` 和 `tsquery`）或引入 Meilisearch/Typesense 以提升搜索性能。
13.翻译按钮：点击切换‘翻译’按钮，网站上的文字会自动切换为中/英文，关于用户发表/发布的笔记/时刻的贴文不用翻译1保持原文，本质只是翻译网站的按钮和ui的文字，
内容行的东西本质不动，以免出现严重错误！
【补充】建议使用 `next-intl` 等国际化方案，将UI文案抽离为 JSON 字典文件。
14.浅色/深色切换按钮：点击切换为浅色/深色模式
15.个人中心：个人中心的按钮替换为头像，鼠标移动到头像展开二级菜单：登陆/注册、个性化、个人主页、账号管理、网站设置（仅为管理员拥有此功能）；鼠标挪开就正常收回
二级菜单
个性化：点击跳转到‘个性化设置’界面->支持编辑上传头像，昵称，编辑上传个人名片，编辑简介
16.通知中心：点击跳转到‘通知’页面，查看收到在评论区的回复，或者聊天室的“有人@你”或者回复，点击可以跳转到对应的评论区/聊天室对应消息，
也能查看到网站的公告和系统更新，点击可以跳转到公告页面，查看自己的时刻贴文收获的点赞或者回复依旧可以点击跳转到对应评论区,
也能查看到自己的主页被点赞，谁点的赞，点赞多少
个，点击即可跳转到自己的个人主页/或者点赞者的主页
【补充】通知的实时推送建议使用 WebSocket 或 SSE，若不要求极高实时性，可在用户切换页面/定时轮询时拉取。
17.同步删除系统：在删除数据库记录的同一段代码（API Route 或 Server Action）里，顺便调用云存储的删除 API 或本地磁盘的 fs.unlink。
注意：如果有多张图片，必须使用 Promise.all 并发删除，或者循环删除。且先删数据库，再删图片（如果先删图片，一旦数据库回滚，图片就彻底丢了）。
引入“文件哈希校验” + 文件资产表 (Asset Table)，避免存在孤儿或重复图片/资源文件

17.主页的其他系统设计：
  1.公告：在主页的正下方，具体可以参考上传的图片文字标注，可以预览文字，点击可以跳转到公告页面，公告只能管理员编辑/发送/修改/删除，支持封面，标题，正文，
  发表的公告显示时间，发布者
  2.美化系统：网站主页、所有的二级页面（仅次于主页，如学习笔记、资源导航、时刻、动漫...）支持樱花粒子效果，支持开启和关闭按钮（默认开启），代码实现以上传的
  文件SakuraPetals.tsx引用；玻璃悬浮、柔和过渡
  3.部分主页布局：以参考图的部分为准，左侧模板为‘主页展示区’展示管理员的‘头像’，‘头像’下方为‘昵称’再下方为‘简介’，‘简介’下面是一排小按钮：关于管理员的如哔哩哔哩主页、github主页、
  网站对应的个人主页的跳转按钮，点击即可跳转到对应的页面；于此同时在这些内容的右侧的大面积的小卡片，四个卡片竖列排列，且分别主标题更名为：学习笔记、资源导航、时刻、公告
  其副标题有时间，字数统计，标签按钮，点击能跳转到对应的页面
  4.‘主页展示区’包含了开发者的头像和昵称，相关跳转，简介，在此下方包含了‘图钉’功能，图钉小卡片会展示被管理员图钉的文章笔记还有时刻，会显示对应的标题文字，
  点击相关的标题文字会跳转到对应的笔记和时刻文章，同时对应的逻辑接口：支持‘图钉’按钮，时刻、笔记是支持被管理员图钉的
  5.同样的右侧展示区提供：网站统计系统、时间日期表格（日历）；统计系统会记录笔记、总标签数、今日访问人数、网站总字数的信息
  6.看板娘：网页桌宠，目前本人暂无相关的概念，但是需要实现Live2D的二次元人物的效果，根据时间、页面内容或特定事件弹出对话气泡，例如提醒休息、问候访客。
  被双击后会有反应生气的气泡对话，例如“变态”，“讨厌，再摸我要生气了”；看板娘右上角支持休息按钮，点击会自动隐藏，并显示在休息中，点击起床切换正常状态
  【补充】技术实现：由于 Live2D 依赖 `window` 对象，在 Next.js 中必须使用 `next/dynamic` 动态导入看板娘组件，并设置 `ssr: false`，否则会报 SSR 错误。
  5.图片相关的系统：所有相关上传的图片的逻辑和接口最大限制在30mb大小，且支持缩放查看，支持自定义裁剪再上传
  【补充】图片展示建议统一使用 Next.js 的 `<Image />` 组件，自动实现 WebP 转换、懒加载和尺寸自适应。
  6.加密系统：支持加密时刻帖子或者笔记，需要输入密码才能查看，
  7.浏览数系统：可以和统计系结合，主要记载笔记和时刻贴文、公告多少人查看，判断逻辑，网页每次点开相应的笔记或者贴文，公告就算一次浏览数
  【补充】防刷机制：单纯的页面点开+1容易被F5刷新刷数据，建议结合 IP + User-Agent + 日期，利用 Redis 缓存做每日去重，同一访客每天对同一内容只计一次浏览量。
  8.标签系统：#example 点击可以跳转到搜索主页，且就可以查看到对应的相关咨询
  9.个人主页：用户点击评论区的头像或者id自动跳转到对应的个人主页，且浏览器的路由显示的不是uuid，而是以@example_username形式出现，
  比如以管理员为例：@allenshiina_admin(仅支持小写数字下划线)包括用户查看自己的个人主页也能展现效果，个人主页也能再‘个人中心’-‘个性化’点击查看，
  主要展示自己的头像、昵称、简介、个性名片、加入/创建的聊天室、发布的时刻贴文
  10.美化系统补充：主页的背景图区（以上传的参考图为例），支持以斜线划分的左右两区域对比效果，支持“背景多图轮播”例如通过JavaScript定时器，
  每隔固定时间（比如20秒）修改一次网页元素的 background-image 样式属性，将背景图替换为图片列表中的下一张，并循环往复
  11.注销系统：已经注销账号的用户，发表的笔记和贴文会保存，其他数据全部清空，且发表的笔记和时刻贴文的发布者会变成“已注销用户”
  【补充】数据完整性处理：建议在数据库中创建一个特殊的“已注销用户”的系统级 ID，注销时，将关联的笔记和贴文的外键 `userId` 更新为该特殊 ID，然后再级联清理该用户的其他相关数据。
  12.主页正中心的文字（参考图里文字）支持修改，大文字标题和副标题，需要还原参考网站的展示效果
  13.第一次注册账号的时候，要强制阅读免责声明，至少需要3s阅读完才能点击我‘已同意，开始注册’，且免责声明是需要写入到‘关于’-‘网站声明’
  14.聊天室的聊天记录仅保存漫游180天，时间过期自动删除痕迹
  【补充】可以通过编写一个基于 Node.js 的定时任务（Cron Job），或者在数据库层面配置定时事件（如 PostgreSQL 的 pg_cron 扩展）每天凌晨自动清理过期数据。
